# UIイメージ集（実装可能な参考例）

`index.html` をブラウザで開くと一覧が見えます。各ページは単体で動き、`common.js` のサンプルデータを使います。
`?state=ok|warn|bad` で3状態（正常／買い停止中／停止）を確認できます。**サンプル値であり実データではありません。**

## 今のUI（apps/web/ops.html）の問題
- すべてのパネルが同じ重みで並び、最初に見るべき答えが分からない
- 表が多く、専門用語（ドローダウン、HALT_NEW_ENTRIES 等）がそのまま出る
- 色・情報量が多く、スマホで読みにくい

## 設計原則
1. 最初の1画面で「正常？ / お金は？ / 今日何した？」に答える
2. 平易な言葉（例: ドローダウン→いちばん減った幅、HALT_NEW_ENTRIES→買い停止中）
3. 詳細は段階的に開示（かんたん→くわしい）
4. 色は 緑／黄／赤 の3つ＋無彩色に限定
5. 時刻は日本時間（JST）を先に表示

## 案
| 案 | 特徴 | 向く用途 |
|---|---|---|
| A ひとこと型 | 状態を一文で示す | 毎日ざっと確認 |
| B 物語型 | 時系列の文章 | 何が起きたか理解したい |
| C ビッグナンバー | 損益が主役、タブ | 成績重視 |
| D コックピット | ダーク、ランプ | 常時モニタ |
| E ガイド付き | 読み方ヘルプ | 初心者 |
| F スマホ | 下タブ | 外出先 |
| G 切替 | かんたん/くわしい | 両立（推奨：A＋G） |

## 表示要素と既存APIの対応（新しいAPIは不要）
| 概念 | 取得元 |
|---|---|
| 正常か／注意点 | `/api/status`（overall, findings, runner, kill_switch, checkpoint） |
| お金・推移・最大減少 | `/api/performance`（summary, series, warning） |
| 今日やったこと | `/api/sessions` |
| 学習・観測 | `/api/observers` |
| 事故記録 | `/api/incidents` |
| 人の買い希望 | `/api/intents` |
| 通知履歴 | `/api/alerts` |

## 実装上の注意
- モックは簡便のため `innerHTML` を使うが、**本実装は `textContent` のみ**（現行 ops.html の方針を維持）
- 読み取り専用・別プロセス・CSP は変更しない。UIから発注や設定変更をする経路は作らない
- 表示値は「最後に記録されたセッション」時点でリアルタイムではない旨を画面に明記する
